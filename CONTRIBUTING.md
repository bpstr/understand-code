# Contributing

Use TypeScript with strict compiler checks and Node.js 22+ built-ins for runtime code. Released JavaScript must have no Python or runtime npm dependency. Keep source discovery separate from semantic interpretation. Source hashes, human notes and explicit unknowns are release contracts, not presentation details.

Install pinned development tools with `npm ci --ignore-scripts`. Edit `src/`, `schemas/` and skill references. Regenerate compiled JavaScript, declarations, schemas and specialist cards with `npm run build`, then run the commands in [testing policy](docs/TESTING.md). `npm run check` independently compiles into a temporary directory and rejects stale bundled files. Add meaningful offline regression coverage for changes to state, evidence, filesystem safety and preservation. Never invoke paid models or load `.secrets` in automated checks. Python files under prepared fixtures are source data; do not execute them or remove their language coverage.

Use a focused branch unless the requester selects another workflow. Write plain-English imperative commit subjects, without type/scope prefixes. Explain concrete behavior changes and validation in pull requests. Update `package.json`, its lockfile, `src/understand_code/index.ts`, both plugin manifests, the marketplace version, changelog, release notes and installation examples together for releases.

For a release, run `npm run release` and `npm run check:artifacts`, then review the plugin ZIP, standalone skill ZIP, npm archive and SHA-256 checksums. These local scripts do not publish. Publishing is authorized by merging a reviewed version change to `main`: after the Node.js 22/24/26 validation matrix succeeds, CI publishes the exact tested commit as `vX.Y.Z` with the checked artifacts and `docs/releases/vX.Y.Z.md` notes. A same-version push does not publish. Existing release tags are never moved or overwritten. An explicit manual workflow run on `main` can retry publication after validation; it still cannot replace a different commit's tag. The GitHub release does not publish to the npm registry.
